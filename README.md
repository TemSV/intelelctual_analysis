# Дашборд аналитика SOC

Локальное приложение на Taipy для одного аналитика SOC. Позволяет разбирать очередь карточек и изучать историческую нагрузку. Исходные данные не изменяются.

## Установка и запуск

Нужен **Python 3.12**. Выполняйте команды из папки проекта. Отдельная сборка интерфейса не требуется.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Перед запуском положите `iavd_incidents_raw_target.parquet` рядом с `app.py`. Датасет предоставляется отдельно и не включён в Git.

Откройте [http://127.0.0.1:5011](http://127.0.0.1:5011). Для остановки нажмите `Ctrl+C` в терминале. Сервер доступен только на локальном компьютере.

Другой файл или порт:

```powershell
.\.venv\Scripts\python.exe app.py --data "C:\data\iavd_incidents_raw_target.parquet" --port 5012
```

В Linux/macOS создайте окружение командой `python3.12 -m venv .venv` и используйте `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`.

## Возможности

- **Разбор очереди:** показатели, фильтры, поиск по точному номеру, непрерывная прокрутка таблицы и открытие карточки нажатием на строку.
- **Состав очереди:** возраст открытых карточек и ведущие типы; фильтры общие с таблицей.
- **Анализ потока:** диапазон дат и переключатель «Нагрузка / Правила / Вердикты». Статус и возраст очереди здесь не применяются; критичность, тип и узел сохраняются.

Фильтр узла содержит шесть наиболее часто встречающихся записей целей в открытой очереди. Поиск ограничивает только таблицу. Сброс фильтров возвращает все открытые карточки и исходный период.

## Краткий отчёт

**Данные.** Использован `iavd_incidents_raw_target.parquet`: 240 295 карточек SOAR, 97 исходных полей, даты создания с 12.04.2024 по 03.09.2025. Одна строка — карточка, которая может объединять несколько событий. Момент среза — 03.09.2025, 15:24:49 MSK, максимум времени создания, назначения и закрытия. Это историческая выгрузка, а не мониторинг в реальном времени.

**Цель и выполненная работа.** Подготовлены данные, реализованы фильтры, показатели, графики и подробная карточка с описанием и техническими полями. Очередь помогает выбрать задачи для проверки; возраст — увидеть накопившиеся карточки; типы и правила SIEM — определить источники нагрузки; вердикты — оценить распределение исходов разбора. Приложение полезно аналитику SOC для первичного просмотра и исследования выгрузки.

**Выводы по исходной выгрузке:**

| Показатель | Значение |
|---|---:|
| Открытые карточки | 164 |
| Из них высокой или критической важности | 49 (29,9%) |
| Открыты более 3 суток | 86 (52,4%) |
| Просрочено взятие в работу | 30 |
| Нет данных о соблюдении срока среди открытых | 1 |
| Ложные срабатывания во всей истории | 150 675 (62,7%) |
| Без вердикта во всей истории | 54 870 (22,8%) |

Более половины открытой очереди старше трёх суток — стоит проверить причины ожидания. Большая доля ложных срабатываний показывает значимость отбора карточек. Частое правило само по себе не доказывает атаку; отсутствующий вердикт нельзя считать ни ложным срабатыванием, ни подтверждённой атакой.

**Методика и ограничения.** Открытая карточка не содержит отдельного токена «Закрыт» в фазе реагирования. Возраст считается от создания до момента среза. Просрочка берётся из исходного флага, пропуски учитываются отдельно. Число карточек не равно числу атак. Вердикты отражают состояние в выгрузке, а не историю изменений; «Решён» не означает подтверждённую атаку. Нагрузка за недели и месяцы выражена в среднем числе карточек за полный календарный день, включая нулевые дни. Неполный день среза исключён из среднего и линий, но учтён в общем количестве. Модель и оценка её предсказаний в эту часть проекта не входят.

## Структура и проверки

- `app.py`, `app.css` — интерфейс, обработчики и оформление.
- `soc/` — подготовка данных и графики.
- `tests/` — проверки на синтетических данных, без исходного датасета.
- `scripts/audit.py` — независимая сверка показателей с Parquet.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -X utf8 scripts/audit.py
```

Сверка требует датасет и сохраняет результат в `output/audit.json`. Для проверки оформления установите `requirements-dev.txt` и выполните `python -m black --check app.py soc scripts tests` в окружении проекта. Проверка оформления и тесты настроены в GitHub Actions.
